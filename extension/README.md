# 译页

无需构建步骤的 Chrome / Edge Manifest V3 扩展。它通过 DeepSeek 兼容的 Chat Completions API，把英文文章正文和常见页面组件原位翻译为简体中文，并只修改现有文本节点的 `nodeValue`。

## 安装

1. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本目录 `extension`。
4. 更新源码后，需要在扩展管理页点击“重新加载”，并刷新已经打开的网页。
5. 测试本地 HTML 时，在扩展详情页开启“允许访问文件网址”。

## DeepSeek 配置

1. 打开扩展设置。
2. 填写 API Key。
3. 默认 Base URL 为 `https://api.deepseek.com`，模型为 `deepseek-v4-pro`。
4. 所有翻译批次最多 1,200 字符，最多允许 500 个在途请求。
5. 初译、全文分析和精校共用统一优先级队列；首屏与屏外初译会立即全部并发启动，全文分析同时在后台运行。遇到 HTTP 429 时自动重试并降低后续批次并发。
6. 点击“测试 API 连接”，确认地址、密钥、模型和响应格式有效。

API Key 保存在 `chrome.storage.local`，只由后台 service worker 读取，不会交给网页脚本。

## 功能

- 一次读取当前 DOM 中全部可见英文文本，覆盖正文、导航、按钮、侧栏、页脚、列表、表格、引用和图片说明。
- 不再根据正文密度、文本长度或是否像人名来判断内容值不值得翻译；模型结合上下文决定专名应翻译还是保留。
- 代码、输入控件、编辑区、隐藏内容、网址和广告区域仍会被排除。
- 常见 UI 短语使用本地词典；较长组件文字通过 API 翻译。
- 表单容器中的文章、帖子和按钮文字可以翻译，但输入框、选择框与编辑区仍被排除。
- 翻译模型按 block 先组织一份完整、自然的中文表达，再把译文分配回原文本节点；普通相邻节点允许移动文字或留空，链接、强调和控件语义仍保留在对应节点。旧版扁平 segment 返回格式仍可安全兼容。
- 内容脚本从 `document_start` 提前运行，用户触发翻译时无需再等待脚本初始化。
- 所有页面内容统一按最高 1,200 字符拆批；当前视口及附近两屏优先进入队列并逐批立即显示。
- 请求队列按“初译、全文分析、精校”排序，后台质量任务不会阻塞新的初译请求。
- 初译使用压缩后的核心提示词，减少每个 1,200 字批次重复发送的提示 token；复杂一致性问题交给全文上下文和后台精校。
- 全文上下文分析与整页初译并行启动，不阻塞任何屏外批次；页面先完成初译，分析结束后仅对可能受术语、指代和语义风险影响的段落进行后台精校。
- 全文分析同时建立章节摘要、跨段指代、说话者关系、文风画像和必须保留英文的名称清单。
- 初译完成后仅选择数字、专名、术语、指代或英文残留等风险段落进行轻量精校，正确译文不会无收益重写。
- 页面先进入完成状态；用户继续停留时才在后台静默精校。单页最多精校 12 个区块或全部区块的 15%。
- 翻译提示词会先重建完整中文表达，再处理 segment，并针对被动句、长定语、关系从句、名词化表达和代词重复调整中文语序。
- 译文返回后会在本地检查数字、否定、情态强度、升降方向、金额与单位、引语归属、术语一致性、保留名称、异常长度和大段英文残留；可疑段落不会进入翻译缓存，并优先进入后台精校。
- 全文分析结果会按页面内容和模型缓存；再次翻译相同页面时不会重复执行分析请求。
- 全文分析默认将输入压缩到约 18,000 字符，保留标题及各段关键首尾，降低长文章开始翻译前的等待。
- 翻译缓存按段落建立，不绑定相邻段落或全文分析 ID；相同段落更容易直接命中缓存。
- URL、代码、编辑区和隐藏内容不会翻译；人名、队名和比分交由模型结合页面上下文处理。
- 批次失败时自动拆小重试，单段失败不会中断整页。
- 只有模型返回格式异常或请求体过大时才会拆小批次，并且最多拆分一层；限流、超时和服务端错误不会引发递归请求膨胀。
- 并发批次的翻译缓存会先在内存中合并，再批量写入浏览器存储，减少长文章后半程的缓存等待。
- 译文返回不等待缓存落盘；缓存写入失败只记录警告，不阻塞页面显示译文。
- 开发者控制台会记录页面扫描、全文分析、API、批次翻译和缓存写入的分阶段耗时。
- DOM 扫描使用防御式包装；单个异常节点或网站组件不会导致整页分析失败。
- 网页右下角提供可拖动控制器，支持翻译、停止、原文/译文切换和 0–100% 进度显示。
- 控制器收起后，首次单击“译”即可翻译；翻译中显示迷你进度条，完成后自动隐藏。
- 完成翻译后继续单击迷你控制器，会在原文与译文之间循环切换；拖动不会误触发操作。
- 控制器会记住展开或收起状态，新页面和新窗口沿用上一次选择。
- 展开或收起时会锁定距离最近的屏幕边缘，右侧浮窗不会在收起后跳到左边。
- 常见单词型菜单标签使用安全词典翻译；其他疑似人名和专有名词交给模型按上下文处理。
- 组件会按导航、菜单、标签页、按钮和状态等语义分类翻译，安全词典仅作为短词兜底。
- 翻译进度按实际字符量加权，长段落和短标签不再拥有相同权重。
- 支持正文直接放在 `body` 下、缺少 `article` / `main` 等现代语义容器的早期网页。
- 论坛主题会识别并翻译全部帖子正文及引用内容，不再只选择文字最多的一条帖子。
- 论坛和单页应用后续动态插入的新帖子、新段落会自动增量翻译。
- 拖动位置保存在浏览器本地。
- 动态新增的可见英文内容会自动进入同一套并发初译与风险精校流程，不重新分析整页。

## DOM 与安全约束

- 不替换正文容器，不重建原有元素。
- 模型译文只写入原文本节点的 `nodeValue`。
- 保留标签层级、属性、链接、图片、表单值、事件监听器和交互。
- API 结果按 segment ID、数量和类型验证。
- 节点被删除或被网站修改后不再写回。
- 不使用 `eval`，不执行模型返回内容。
- 悬浮控制器位于隔离的 Shadow DOM 中，并被正文扫描明确排除。

## 已知限制

- 不支持 PDF、图片 OCR、iframe 内容和封闭 Shadow DOM。
- 页面刷新后，当前节点引用和原文/译文显示状态会丢失，但翻译缓存保留。
- 动态内容只有在网站插入到当前页面后才能翻译；尚未滚动加载的帖子需要先进入页面。
- 短词存在语义歧义，因此组件模式会保守跳过疑似人名、队名和单独专有名词。
